larger:, smaller: and size: in Gmail Search: What's the Difference?

Updated October 2026 · 4 min read

Quick answer: In Gmail search, larger: sets a lower size limit and smaller: sets an upper one. Both accept a unit, as in Google's example larger:10M. size: takes a plain number, as in Google's example size:1000000, but Google doesn't say whether it means "at least" or "exactly". For cleanup on a computer, use larger: and smaller:, combining them for a range such as larger:5M smaller:10M. Gmail filters by size; it does not sort largest first.

Google's Gmail search operator reference puts all three operators in one row, describes them only as "Find emails by their size", and gives two examples. Everything else people say about them, including in many guides, is inferred. This page separates what Google documents from what it leaves out and gives you a quick way to check the gaps in your own mailbox. If you already know which query you want and need the deletion steps, use how to delete Gmail emails by size safely.

Many third-party guides describe size: as a bytes-only version of larger:. That may be right, but Google doesn't state it. An exact-size match is rarely useful anyway, because you almost never know a message's size to the byte. For practical searches, larger: and smaller: say what they mean.

Keep the numbers whole. Google notes that in search, a space or a dash separates a number and a dot is a decimal point, but it doesn't say whether size operators accept decimals. If you need 2.5 MB, larger:2500000 sidesteps the question, at the cost of assuming a plain number means bytes.

How can I test where the thresholds fall in my own mailbox?

A message is usually bigger than the file attached to it. Email sends attachments as text using Base64 encoding, which RFC 2045 defines as turning every 3 bytes into 4 characters. That makes the encoded attachment about a third larger, before headers and the message body are added. Google doesn't say whether its size search counts the encoded message or the original file. You can find out in a few minutes with a test message whose size you know.

  1. Pick a test file of known size. Choose a photo or PDF of about 3 MB and note its exact size in bytes from your computer's file information panel.
  2. Email it to yourself. In Gmail on a computer, send a new message to your own address with the file attached and a unique subject such as size-test-3mb.
  3. Bracket it with thresholds. Search subject:size-test-3mb larger:2M, then larger:3M and larger:4M, then subject:size-test-3mb smaller:4M. Write down which searches return the message.
  4. Read the result. The highest larger: value that still returns the message and the lowest smaller: value that returns it bracket the size Gmail uses. If the message matches larger:3M or higher although the file was just under 3 MB, that suggests Gmail counts the whole encoded message, not the raw file. Add size: with the file's byte count to see how it behaves.
  5. Remove the test messages. Delete the sent and received copies. They move to Trash, where Google's deletion and recovery help says they stay recoverable for 30 days.

We have not run this test for this article, so no expected results are given here. The method is the point. If your result surprises you, adjust your thresholds by the margin you saw before searching your real mail.

Why doesn't Gmail list results largest first?

The size operators filter results; they don't sort them. Gmail's search reference documents no sort-by-size option, so the matching conversations appear in the usual date order. To get closer to a largest-first view, start with a high threshold and work down. Each pass shows a smaller, heavier group. Remember that a result count is a number of conversations, not bytes, so it can't tell you how much storage you will get back. For the account-wide picture, see how to free up Gmail storage.

Why does a size search show conversations with small messages?

Gmail matches individual messages and then shows their conversations. Google explains this for negative searches, noting that Gmail "identifies matching messages first", so a -is:starred search can still return a conversation containing a starred message. The same display applies to a size search. One large message can bring up a conversation full of small replies, and deleting the conversation removes all of them. Open results before you select them. When is a size search the wrong tool?

Size searches suit a few heavy messages. If your mailbox is full of thousands of small newsletters and notifications, no size threshold will isolate them. Clearing the senders will. Inbox Cleaner runs in an open Gmail tab in desktop Chrome, groups senders by email count and moves the selected senders' emails to Trash. It can't apply a size limit: everything from a chosen sender goes, large or small. Counts are email counts, not storage. Stay with native size searches when size is the reason you're deleting. Frequently asked questions

Can I use K for kilobytes, like smaller:500K?

Google's reference only shows an M example (larger:10M) and a plain number (size:1000000). Other units are not documented, so run the known-size test before relying on them, or use a plain number of bytes.

Is 10M ten million bytes or 10 MiB?

Google doesn't say. The two differ by about 5%, which only matters for messages close to the threshold. Leave a margin, or bracket the message with the known-size test.

Can I search for a decimal size such as larger:2.5M?

Google notes that a dot in a search number is read as a decimal point, but it doesn't say whether size operators accept decimals. A whole number in bytes, such as larger:2500000, avoids the question.

Is the Size field in Gmail's search options the same thing?

Google describes the Size field in the search options panel only as searching for emails that match a certain size. Use it, then look at the query Gmail puts in the search box and compare the results with your typed search.
