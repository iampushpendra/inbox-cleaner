Inbox Cleaner Setup, Permissions and Trash Recovery

Published October 17, 2026 · By Inbox Cleaner · Source review, not a live mailbox test

Quick answer: Inbox Cleaner’s reviewed extension source works through an open Gmail tab in desktop Chrome. It builds a sender list, then uses Gmail controls to move selected senders’ matching mail to Trash after confirmation. A separate Gmail search’s date, size, category or star restrictions do not carry into that action.

This guide explains the repository’s extension runtime version 3.2.1, reviewed October 17, 2026. We have not verified the installed Chrome Web Store package or performed this workflow in a live mailbox. Check the installed version and permissions before relying on a feature described here.

Set up the extension and choose the Gmail account

  1. Review the Chrome listing, its publisher and permission prompt. Install only if those match your expectations.
  2. Open Gmail in desktop Chrome and sign in to the intended account. Keep only that account’s Gmail tab open during setup: the reviewed code picks an active Gmail tab, or the first available Gmail tab. The popup is not an account picker.
  3. If Gmail was open before installation, reload it so the content script can attach. Open the extension popup and choose Scan my inbox.
  4. Wait for the scan state to finish. The scan navigates Gmail category pages and sender searches; duration depends on the mailbox and available page controls. A stalled or incomplete scan is not a complete inventory.
  5. Review sender addresses and count qualifiers. Select only senders whose matching mail you are willing to clear across Gmail, including archived mail. Read the confirmation before choosing Move to Trash.

Do a small review first. If you need to keep recent mail, starred items or particular receipts from a sender, use Gmail’s native search and selection workflow for that narrower task instead.

What do the permissions and data flow mean?

  • Gmail host access: https://mail.google.com/* lets the content script read rendered Gmail information and operate Gmail controls. This is consequential access to a signed-in page.
  • tabs: the popup locates a Gmail tab and sends it scan/action messages.
  • storage: scan results are cached under inboxCleanerData in Chrome extension local storage. The stored object includes senders, a scan timestamp and count metadata.

The reviewed flow is: Gmail’s rendered sender/date information → extension parsing → local sender cache → popup selection → new sender queries in Gmail → Gmail’s Trash control. The reviewed extension has no independent network client, OAuth sign-in, Gmail API client or model API. Gmail itself still communicates with Google. This is a source-level description, not a network capture or a guarantee about a different installed package.

The website is a separate surface: hosting, external resources and explicit waitlist submissions have their own data flow. The optional legacy browser app uses OAuth and the Gmail API. Read the privacy policy’s separate product descriptions; do not apply extension statements to the whole website.

Why can the action cover more than the scan suggests?

The scan discovers senders through five category views. Sender counts come from Gmail conversation/result counters where resolvable, with counting limited to the top 250 senders; other counts may be estimates. These are not byte measurements, a promise of unique messages, or proof that every mailbox item was scanned.

Synthetic worked example: a sender has one old promotional conversation in the inbox and one recent archived receipt. You first search Gmail for old promotions. Selecting that sender in the extension still starts a fresh sender-wide search; the archived receipt is in scope. The earlier date/category restriction is not inherited. This example explains query scope, not a recorded Gmail result.

Selected senders are processed in groups of up to 20. Conversations involving more than one selected sender may overlap, so adding sender counts need not equal unique conversations affected. Review the native Gmail comparison when the action needs precise search restrictions.

How to recover mail moved to Trash

In Gmail on a computer, open More → Trash, select the mail to restore, choose Move to and a destination. Google documents a normal recovery window of up to 30 days; permanent removal sooner ends that option. The extension has no built-in Undo feature. Google’s deletion and recovery instructions explain the limits.

Keep recovery separate from storage cleanup. Moving mail to Trash does not demonstrate freed space; mail in Trash still uses storage. See the storage cleanup guide before making an irreversible storage decision.

If Gmail is not found or a scan fails

Confirm Gmail is open in the Chrome profile where the extension is installed, reload Gmail, and reopen the popup. Check the extension’s site access in Chrome’s extension details. If counts remain incomplete or controls fail, stop before confirming a sender-wide action and use Gmail directly. A Gmail layout change, restricted extension access or multiple tabs may need investigation; repeating an uncertain action is not evidence of success.

You can disable or remove the extension from Chrome’s Extensions → Manage extensions page. That does not reverse Gmail actions already performed. Chrome’s extension management guide covers site access and removal.

Plan a narrower cleanup locally

The local Gmail cleanup search builder can help draft a query for a native Gmail task. It does not inspect your mailbox or apply those restrictions to the extension. The storage troubleshooter helps choose a storage investigation path using your own inputs.
