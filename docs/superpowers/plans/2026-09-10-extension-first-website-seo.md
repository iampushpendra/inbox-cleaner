# Extension-First Website & SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Inbox Cleaner web property into a marketing landing page that drives Chrome Web Store installs, and retarget the SEO/content pipeline from "sign in to the web app" to "install the extension."

**Architecture:** `docs/index.html` is rewritten as a zero-JavaScript landing page; `docs/app.js` (the dead OAuth web app) is deleted outright and its dead CSS stripped from `docs/style.css`. Store screenshots are generated by rendering the real `popup.html` in headless Chrome with a stubbed `chrome` API and demo data, so they can never drift from the shipped UI. The content pipeline's CTA template and topic queue are retargeted, and 15 published posts are retrofitted.

**Tech Stack:** Static HTML/CSS, no build step, no dependencies. Headless Chrome (v152, already installed at `/Applications/Google Chrome.app`) for screenshot capture. Python 3 only where `publish_blog.py` already uses it.

**Spec:** `docs/superpowers/specs/2026-09-10-extension-first-website-seo-design.md`

## Global Constraints

- **Store URL — the single value every CTA uses, verbatim:** `https://chromewebstore.google.com/detail/inbox-cleaner/pnlnpdidhjimchppdmojledmfakpepep`
- **Canonical host:** `https://inbox-cleaner.vercel.app` — unchanged. Do not introduce the GitHub Pages URL anywhere.
- No new dependencies, no build step, no `package.json`.
- **Landing page ships zero JavaScript.** No `<script>` tags except `application/ld+json`. The Google Fonts stylesheet stays (all 16 blog pages use it); no analytics or tracking of any kind.
- **Claims discipline — only these privacy statements are permitted**, each verified against shipped v3.0.0 code: no Google sign-in / no OAuth / no API access; makes no network requests at all; reads only sender name, address and date from already-rendered rows; scan cache lives in `chrome.storage.local` on the device; mail moves to Trash (recoverable ~30 days), never permanent deletion.
- **Never claim** the extension "cannot see" your email — the content script can read the page it runs in. The accurate claim is that nothing is transmitted.
- **Never make claims about a named competitor's data-handling conduct.** The comparison table uses the generic column label "Typical cleaner apps" and compares capability axes only.
- **Two claims that are now false and must not survive anywhere:** "No install / runs in your browser", and any scan-speed promise like "about 30 seconds for 5,000 emails" (DOM scanning is materially slower than the old API calls).
- Follow existing class names in `docs/style.css`. No inline styles on the landing page.

- [ ] **Step 3: Create `scripts/generate_screenshots.sh`**

```bash
#!/bin/bash
set -euo pipefail
cd "$(dirname "$0")/.."

CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
TMP=".screenshot-tmp.html"
OUT="docs/img/screenshots"

if [ ! -x "$CHROME" ]; then
  echo "Chrome not found at $CHROME" >&2
  exit 1
fi

mkdir -p "$OUT"

# Inject the frame stylesheet and the harness (which must load before popup.js).
sed -e 's|<link rel="stylesheet" href="popup.css">|<link rel="stylesheet" href="popup.css">\n  <link rel="stylesheet" href="scripts/screenshots/frame.css">|' \
    -e 's|<script src="popup.js"></script>|<script src="scripts/screenshots/harness.js"></script>\n<script src="popup.js"></script>|' \
    popup.html > "$TMP"

for state in ranked-list search-sort selection confirm; do
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars \
    --window-size=1280,800 \
    --virtual-time-budget=4000 \
    --screenshot="$OUT/$state.png" \
    "file://$PWD/$TMP?state=$state" 2>/dev/null
  echo "captured $OUT/$state.png"
done

# Social preview image — og:image in docs/index.html points here.
"$CHROME" --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1200,630 \
  --virtual-time-budget=4000 \
  --screenshot="docs/og-image.png" \
  "file://$PWD/$TMP?state=ranked-list" 2>/dev/null
echo "captured docs/og-image.png"

rm -f "$TMP"
echo "Done. 4 screenshots in $OUT, plus docs/og-image.png"
```

Moving mail to Trash is done by operating Gmail's own bulk-action controls, only when you click Move to Trash. Trashed mail is recoverable in Gmail for about 30 days.
- **Permissions and why** — `storage` (caching scan results locally so you don't rescan on every popup open); `tabs` (finding your already-open Gmail tab to send the scan/delete command to — it does not read the contents of any other site); host access to `mail.google.com` (running the content script inside the Gmail page — the only site the extension can touch).
- **Data retention** — nothing is retained by the developer, because nothing is transmitted. Clear the local cache any time via Chrome's extension settings or by removing the extension.
- **Third-party access** — no data is sold, shared, or transferred to anyone. There are no third parties, because there are no network requests.
- **Removing the extension** — uninstall it from `chrome://extensions`. Because it never had access to your Google account, there is nothing to revoke at myaccount.google.com.
