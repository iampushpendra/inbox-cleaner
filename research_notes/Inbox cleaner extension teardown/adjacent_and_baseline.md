# Adjacent inbox cleaners and local Inbox Cleaner baseline

Researched 2026-10-17. Public primary sources and local source inspection only. No installation, authentication, or mailbox operations. Chrome unavailable in browser runtime. Two Leave Me Alone official screenshot assets were downloaded and visually inspected; other visual quality is explicitly unassessed. Documented flows are not hands-on tests. Product claims are attributed, not independently audited.

## Which major alternatives are actual Chrome extensions, and what do adjacent services provide?

### Takeaway
These five familiar names should be in an adjacent-services comparison, not presented as verified Chrome extensions. Their official surfaces describe web/cloud/mobile delivery; absence of an official extension is a verification gap, not proof none exists. Gmail's native subscription manager is the most important zero-install baseline.

### Cited Findings
- **Clean Email — cloud/web, iOS, Android, Mac.** Bulk grouping, smart folders, cleaning suggestions, archive/move/label/trash, unsubscribe, Read Later, Pause, Keep Newest, Auto Clean rules, Screener. Gmail OAuth; vendor says headers/metadata processed, bodies/attachments not downloaded, metadata stored 45 days, no sale of email data. CTA vocabulary: “Try for Free”, “Try it Now For Free”, “Get Started for Free.” [Official homepage](https://clean.email/).
- **Clean Email free limits:** 1,000 message cleaning allowance; premium features require subscription or 14-day trial, no card, plus 25 unsubscribe actions. Paid upgrade charged immediately even during trial. [Free trial documentation](https://clean.email/help/accounts/free-trial-and-subscriptions). Enabling reminders grants 100 additional cleaning actions weekly. [Reminder allowance](https://clean.email/help/accounts/cleaning-more-messages-for-free). Official plans are for 1, 5, or 10 accounts, with monthly/yearly choices, all premium features, cloud processing; dynamic dollar values failed to render, so do not publish scraped or third-party dollar estimates. [Plans](https://clean.email/plans).
- **Cleanfox — web/mobile adjacent service.** Official FAQ names web browser access on computers and mobile/tablet application, three choices: remove old mail, remove old and automatically trash future mail, keep. This is not necessarily a true sender unsubscribe. [FAQ](https://www20010.cleanfox.io/fr-fr/faq.html). Free service finances itself through commercial statistics derived from newsletters and transactions; NielsenIQ consumer-panel membership disclosed. [Official English page](https://www.cleanfox.io/en-GB). Privacy page describes commercial email copies and transactional information collection; Gmail use is restricted to providing inbox/subscription services, including Limited Use transfer provisions. [Privacy](https://web.cleanfox.io/en-gb/privacy.html). Do not reduce this nuanced model to “all Gmail data sold.”
- **Cleanfox documented interaction:** card swipe left auto-deletes existing/future newsletter mail, up removes existing only, right keeps. List view supports multi-selection; red circle = automatic delete, orange trash = existing only, green box = keep. Shows sender received count/opened count. [Official how-it-works](https://web.cleanfox.io/fr-fr/how-it-works.html). Current appearance not visually inspected; older documented interaction may differ from 2026 product.
- **Unroll.Me — web plus iOS/Android.** Official device guide explicitly identifies website on computers and mobile apps; recommends mobile for easier Gmail connection. [Devices](https://support.unroll.me/hc/en-us/articles/31997799536653-What-devices-can-I-use-Unroll-Me-on). Primary choices Keep / Block / Rollup into daily digest; current homepage calls it blocking rather than promising true unsubscribe. [Homepage](https://unroll.me/). Free to users per [cost FAQ](https://support.unroll.me/hc/en-us/articles/200200917-How-much-does-Unroll-Me-cost). Current business explanation says commercial-email information/demographic details support measurement, advertising products and datasets sold to businesses/data brokers. This newer statement is more nuanced than old FAQ “anonymized only” wording. [December 2025 data explanation](https://support.unroll.me/hc/en-us/articles/115005696183-What-do-we-do-with-your-data); [privacy notice](https://unroll.me/legal/privacy/).
- **Unroll.Me desktop Gmail onboarding friction:** official February 2026 instructions enumerate 15 steps: signup → Add Mailbox → Google → address → manual signup below QR → data consent → enable Google 2FA → create app password → paste password → connect. Work/school accounts may not support this. This is provider/account specific; do not claim all services use app passwords. [Official Gmail instructions](https://support.unroll.me/hc/en-us/articles/4423682917133-How-to-connect-your-Google-mailbox-to-Unroll-Me).
- **Leave Me Alone — website and mobile apps.** Unsubscribe with actual sender requests, rollups, screener, spam blocker, priority senders, DND, multiple accounts. 10 free unsubscribes, no card; Seven Day Pass description says $19, two accounts and seven days unlimited unsubscribes, but dynamic pricing card also rendered erroneous $0 values. Use $19 only as documented description, flag checkout price unverified. [Homepage](https://leavemealone.com/); [apps](https://leavemealone.com/apps/).
- **Leave Me Alone permissions/data:** Gmail OAuth connect with “Connect to Google”, review permissions; guide warns permission wording includes reading/composing/sending and mail settings. [Gmail connection](https://help.leavemealone.com/en/connecting-your-email-account/how-to-connect-a-gmail-account). Privacy says unsubscribe-only stores metadata; rollups store selected senders' content; Screener stores sender metadata; optional Spam Blocker processes bodies and retains classifier-training samples on its own infrastructure; delete-account exceptions include encrypted backups up to 90 days and training samples expiring separately. No user-data sale. AI summaries process sender/subject on self-hosted open-weight models; Spam Blocker off by default. Therefore do not label the whole service “never reads email content.” [August 2026 privacy policy](https://leavemealone.com/privacy/).
- **SaneBox — service in existing mail client; no download required.** Filtering importance, follow-up reminders, BlackHole, Daily Digest. [Homepage](https://www.sanebox.com/). Deep Clean, SaneLater, SaneNews, BlackHole, reminders, digest documented. [Tour](https://www.sanebox.com/learn). Seven-day trial, Snack 1 account/2 chosen features; Lunch 2 accounts/6 per account; Dinner 4 accounts/all. A public official pricing variant shows $4.54/$7.46/$22.04 per month **paid biyearly**; standard pricing page rendered no dollar values. Never present these as monthly subscriptions or default prices. [Official pricing variant](https://www.sanebox.com/buy/latte_202109_biyearly); [plan help](https://www.sanebox.com/help/201-which-subscription-plans-can-i-choose-from).
- **SaneBox privacy:** headers analyzed; optional features may retrieve bodies without storing them; password/OAuth credentials encrypted; CASAs claimed annually. [Security](https://www.sanebox.com/security). Public security promises are not a local-processing architecture.
- **Gmail native Manage subscriptions:** launched July 8, 2025; frequency-sorted senders with counts for past few weeks, sender drilldown, unsubscribe requests, web/Android/iOS rollout in selected countries. [Google announcement](https://blog.google/products-and-platforms/products/gmail/new-manage-subscriptions-unsubscribe/). Current help still warns gradual availability; More → Manage subscriptions → Unsubscribe; name/avatar opens all sender messages; unsubscribe affects all active lists related to that sender. Sender website may be required; Block alternative sends future mail to Spam. [Current Gmail Help](https://support.google.com/mail/answer/15621070?hl=en).

### Inferences
- Distinguish three user jobs in the report: old-message cleanup, stopping future mail, recurring organization. Local Inbox Cleaner currently solves the first; its “delete them” wording can be mistaken for unsubscribe or sender blocking.
- Gmail's recent-frequency list establishes a strong free baseline; compete on historical volume and trustworthy bulk review, not merely “see your subscriptions.”
- Local no-OAuth processing can remove substantial signup anxiety relative to Unroll.Me's desktop connection flow. Conversely cloud tools can continue scans while browser is closed; local automation needs explicit operating constraints.
- SaneBox's named folder concepts add vocabulary cost; “Move to Trash” is easier to predict than “BlackHole”, but less comprehensive in ongoing prevention.

### Gaps
- No official Chrome listing confirmed for any of these five; classify as adjacent based on documented platforms, not categorical nonexistence.
- Exact standard current paid prices for Clean Email, SaneBox, Leave Me Alone could not be verified from dynamically rendered price controls. Do not copy competitor-written comparison figures.
- Cleanfox routes delivered inconsistent content (empty localized HTML, indexed older pages and newer marketing variants); exact live onboarding/auth mechanism not proven. Prefer primary privacy and clear documented workflow caveats.
- No authenticated onboarding completion, measured speed, or real unsubscribe efficacy tested. Visual design scores unassessed except limited LMA screenshot assessment below.

## What does the observed onboarding and CTA design teach us?

### Takeaway
Leave Me Alone offers the strongest directly inspected evidence here: one email-address field on onboarding, and self-contained sender rows with explicit text actions. Its scan documentation is unusually useful because it states both duration and search scope.

### Cited Findings
- **Observed official screenshot: onboarding.** White/pale pink page; envelope mascot; welcome speech bubble; spacious card “Let's connect your first email account!”; one large account-email input with helper “Enter a valid email address above to see some more options.” Menu isolated top-right. Annotated support screenshot; not live UI. [Official screenshot](https://help.leavemealone.com/api/images?id=17d65b70-c582-472c-90f8-3dadc35d4a16); source [connection guide](https://help.leavemealone.com/en/start-here/first-steps/step-1-connecting-your-first-email-account). Local evidence: `evidence/lma-onboarding.png`.
- **Observed official screenshot: sender row.** White border card; prominent “12 monthly” at left, name Example plus hello@example.com; three pale-pink pill buttons “Keep in Inbox”, “Add to Rollup”, “Unsubscribe”, each with distinctive envelope icon. [Official screenshot](https://leavemealone.com/_astro/mail-item-example.DDBedF3c.png); [workflow guide](https://leavemealone.com/learn/). Local evidence: `evidence/lma-mail-item.png`.
- **Documented scan expectation:** most LMA scans take minutes; user can leave page; background continues and completion notified. Default discovers mailing-list emails received past six months, inbox plus user folders, excludes Spam/Trash with opt-in option. [Scanning guide](https://help.leavemealone.com/en/start-here/first-steps/step-2-scanning-for-emails).
- **Documented Clean Email review safety:** click sender/group for subjects preview, explicit confirmation of unsubscribe, existing-message Trash toggle on by default, confirmation-suppression option creates a stated risk of subsequently trashing messages without prompts. [Unsubscriber guide](https://clean.email/help/tools/unsubscriber). Bulk flow also confirms whether existing mail should be trashed. [Bulk unsubscribe](https://clean.email/help/questions/how-can-i-unsubscribe-from-emails-in-bulk).

### Inferences
- LMA screenshot-only design assessment: strong visual consistency and large readable named buttons; “monthly” labels temporal scope better than an unlabeled count. Friendly mascot reduces form anxiety. Equal emphasis on all three buttons avoids pressure but weakens primary-action prioritization; unfamiliar “Rollup” requires adjacent explanation. Wide desktop row will need a different narrow-popup treatment. Placeholder and helper appear low contrast; no contrast measurement conducted. Do not turn these observations into a numeric global product score.
- LMA onboarding has a clear single field, but “see some more options” is vague about permission/auth next steps; a concise preflight can outperform it by stating what the extension reads and what scan does.
- Cleanfox's three gesture directions and color-symbol mappings create memory burden; explicit labels beside icons are safer for a desktop cleaner. This critique is inference from documented interactions, not inspected contemporary UI.
- “Try for Free” is lower commitment but generic. Local “Scan my inbox” is more concrete; improve to “Scan Gmail senders” to avoid Inbox-only scope confusion.
- Best pattern to borrow immediately: before scan, explain “Usually takes a few minutes”, what folders are covered, whether user may close popup versus Gmail, and that nothing is trashed by scanning.

### Gaps
- Cannot score overall visual polish or accessibility for Clean Email/Cleanfox/Unroll.Me/SaneBox without current screenshots/live inspection. Clean Email official SVG screenshot downloaded to /tmp but not rasterized/inspected (cairosvg unavailable); no visual claim based on it.
- No observational evidence for actual post-auth mobile screens, success notifications, keyboard control or responsive behavior.

## What should local Inbox Cleaner improve relative to these benchmarks?

### Takeaway
Local product has a compact, comprehensible core action and valuable privacy architecture. Its biggest competitive risks are account identity, inconsistent scan/delete scope language, approximate totals presented as exact in the selection bar, and lack of review/undo guidance—not lack of additional features.

### Cited Findings
All below are **source-observed**, not rendered UI or reproduced bugs. Sources are workspace files at `/Users/pushpendrasingh/projects/inbox-cleaner/`.

- README version 3.2.1 documents DOM automation, no OAuth/API/backend for extension, local cache, 5-category discovery, exact counts for top 250 senders only, remaining counts marked ~, scans taking minutes, English UI only, and Gmail DOM dependency. Separate web app uses Gmail API and OAuth. [README](../../README.md); [manifest](../../manifest.json).
- Empty screen has emoji hero, heading, “across every category — then delete them”, single “Scan my inbox” CTA. No timing/privacy/safety preflight in popup. No-Gmail screen says open/reload Gmail but only offers “Retry” rather than opening Gmail. [popup.html](../../popup.html).
- Compact fixed 400×580 popup; system sans 13px, title 15px, sender metadata small, white/light-gray surfaces, blue selection, red danger. Dark palette changes accent to #8ab4f8 while primary text remains white, plausibly weak contrast; no measured accessibility pass. [popup.css](../../popup.css).
- Sender rows show name/address/category/latest, count chips with exactness tooltip; whole-row click toggles selection. Refresh icon uses title “Re-scan inbox”. No obvious message-preview link. Sticky selected-action bar uses “Clear” and “Move to Trash”. [popup.js](../../popup.js); [popup.html](../../popup.html).
- `updateActionBar()` sums stored counts and prints N emails without approximation even if any selected sender has a sampled count. Confirmation correctly says “at least N” for mixed/approximate selection, and “All Mail including archived” for exact selection. This is a concrete copy inconsistency. [popup.js](../../popup.js).
- `findGmailTabId()` picks active Gmail tab, else first Gmail tab; cache is globally stored under `inboxCleanerData`, without account identifier in the observed stored payload. Header displays counts/time, not account email. `init()` can show cached results even if content script unavailable. These facts create an account/cache trust risk, but no wrong-account deletion was reproduced. [popup.js](../../popup.js); [content.js](../../content.js).
- Scan progress reports scanning category N of 5 then counting sender N of total, detail truncated to 34 characters; no stop/pause CTA in popup. Delete success toast only “Deletion complete ✓”; README proposes future undo. Modal discloses 30-day Trash auto-purge. [popup.js](../../popup.js); [popup.html](../../popup.html); [README](../../README.md).

### Inferences
1. **P0 scope/count safety:** align header, row, sticky bar, confirmation and post-action report around same units (messages versus conversations), time/folder scope and exactness. Put “at least”/“estimated” in sticky total as soon as one approximate sender selected. For destructive operations obtain an exact preflight count or require explicit review of wider All Mail scope. Do not let visual badges imply category-scoped deletion when the action affects archived mail too.
2. **P0 account certainty:** display account identity before scanning and acting; namespace cache by Gmail account; bind scan/session/action to same tab/account, and require rescan when they mismatch. This is more important than adding unsubscribe.
3. **P1 before scan:** one concise panel: “Find senders across Gmail categories. This may take several minutes. Nothing moves until you review and confirm. Runs locally in this browser.” State accurately what can close and what must remain open based on actual implementation. Make no unsupported promise to work with Gmail closed.
4. **P1 progress and recovery:** phase-aware progress (“Discovering senders”, “Verifying counts”), elapsed time, counts found, clear status; stop/cancel if architecture supports. Preserve last successful results but visibly label stale/incomplete data and disable action when account unavailable. Explain Gmail navigation because automation changes the page.
5. **P1 review and recovery:** “View messages in Gmail” per sender and chosen batch; explicit account/scope summary, include excluded protections if implemented, then named action. Post action show verified moved/failed count and “Open Trash”/“How to restore”. A true Undo button requires reliably tracking message IDs/actions; do not fake reversal through a broad sender query.
6. **P1 privacy comprehension:** surface local/no OAuth/no server beside first scan, plus short explanation of Gmail host permission. Keep web app and extension privacy promises distinct. Local processing does not mean no network traffic: Gmail itself remains online.
7. **P2 understandable navigation:** “Clear selection”, text-labeled Rescan, “Open Gmail” for missing tab. Explain count-chip color means volume, not risk/importance. Review buttons need visible keyboard focus, label/input association and proper dialog semantics; source alone cannot prove actual accessibility.
8. **P2 feature scope:** archive or age filters could satisfy caution without cloud automation; leave unsubscribe, daily digests, AI classifications for later until core account/scope/count trust is established. Maintain compact list; do not copy broad cloud suite navigation into popup.

### Gaps
- No local UI rendered and no mailbox touched. Findings are source-based and need behavior validation before treating them as reproduced defects.
- README claims of local-only behavior were not exhaustively network-audited.
- Relative links in these notes need conversion to absolute workspace file links if excerpts are moved into final report.
